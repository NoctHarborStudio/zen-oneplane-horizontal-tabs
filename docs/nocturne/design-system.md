Status: DS-M1 source audit complete, native confirmation open. Baseline `0.3.0-preview.202`, `81b0a76612546cc72c5d5a0ccbed7eb3ff75a2df`, 2026-11-24. ## Agreed requirements

- Start with material, including the entire top plane and bookmarks region. Remove the visible bookmark-local background halo on light pages; one common backing across tabs, address and bookmarks, not stacked row fills. Keep interactive controls and existing Magnetic Bookmarks motion.
- Default visual target is the previously demonstrated translucent glass near 70%. Working convention: **70% tint opacity (30% transmission before blur)**, not 70% transmission; explicitly label the setting and adjust after visual comparison. No opacity on text/icon ancestors merely to tint a surface.
- One global configurable material; individual surfaces inherit each property by default and may override it independently. The local override is opt-in; resetting restores inheritance, not a copied value. Keep existing data and native commands.
- Home Search and top address search, Hub and Downloads, History/Library must look and move like one product. Restore compact All Downloads expansion in the same anchored Downloads panel; retain full Library and its Downloads section via Library navigation. No second data cache.
- Motion comes after material: common easing/phase language, reversible interruption, real live content, no final-frame color/text changes. Preserve existing proven motion until its migration.

### Bookmark halo: source-confirmed shape, native cause not yet isolated

`contourImage` composites the vertical fade and a solid path inside one SVG group, with global opacity applied once. `contourGeometry` computes base from nav/row bottom minus trim, then derives deep/left/right from visible bookmark controls or the stable envelope. It is not evidence of a second independent renderer. A brighter/darker local plateau can exist where the path extends below the gradient hold; the user's screenshot shows a bookmark-local protruding boundary, consistent with this geometry. At default settings the effective alpha outside the path is 0.960 at 30px below base, 0.855 at 40px, 0.596 at 50px, 0.261 at 60px and zero at 69px; the solid path remains 0.960 inside. Actual Gecko backdrop pixels depend on compositor/native styles.

Source-backed isolated V8 probe using real contour functions: synthetic 1920px wrapper, 52px nav/row, 24px bookmark at y=52, growth 7px vertical/15px horizontal. Visible envelope base/deep=47/76, stable=47/83, no bookmarks=47/47 (no shelf). This demonstrates the geometry path; it is not a measured screenshot or proof of all halo causes. The reduced-transparency row fills and workspace transient backing are separately confirmed source paths, not proven causes of the resting screenshot.

Compare implementation options: (1) tune current shelf radius/opacity: leaves the bookmark-local outline, rejected as final solution; (2) one existing surface with flat, full-width measured row envelope and single downward fade: preferred; (3) replace with multiple glass panels or extra layer: reintroduces compositing seams and ownership, rejected. Retain Geometry Coordinator and actual row metrics; derive flat bottom from visible row/hover reserve and bounded measured toolbar geometry, not individual bookmark extents. Bookmark hidden/visible, overflow rows, persistent, compact and native fallback remain distinct. Keep old code until new path passes tests; remove dead shelf/provider consumers only after cutover, not the Magnetic Bookmarks controller. Verify which provider consumers remain before deletion.

## Material architecture (DS-M2–M7)

Proposed implementation order inside material stage (dependencies precede adoption):
1. DS-M2/M4: define canonical palette + semantic properties (tint, tint opacity, blur, radius, border, shadow, foreground, control-state fills) and pure resolution/clamping. Use shared CSS custom properties in generated stylesheet; evaluate Sine preference schema and existing pref lifecycle before choosing dynamic binding. No independent observer per panel, no new background DOM when existing one suffices. Use theme-adaptive light/dark values, forced-colors/reduced-transparency safety and opacity separately from motion.
2. DS-M5/M6: per-property resolution global → role → explicit component override. Suggested roles top-plane, anchored-panel, modal-panel, search, control; role values inherit globals except structural shape/geometry. Global default 70% tint opacity, proposed blur 24px, panel radius 12px, soft border/shadow; numeric visual defaults are provisional except agreed approximate opacity. Use one canonical setting and explicit local inherit/override; validate 0 and 100, absent/invalid preferences, live changes, restart, multi-window, unload. Do not blindly replace user's old prefs: legacy fade-transparency currently means inverse alpha, range 0–40; fade strength/curve/length/hold/padding/radius and stable-background have distinct geometry/visual responsibilities. Document mapping and precedence, avoid two simultaneous opacity controls; retain saved prefs for compatibility until retirement is justified. Home tint/OS transparency are separate.
3. DS-M3: first actual consumer: top plane. Keep one #oneplane-toolbar-surface; use one uniform fill across occupied rows and one full-width lower fade, no bookmark-local silhouette. Choose exactly one opacity application for tint and blur/fade (compare CSS mask vs tint alpha in Gecko; avoid 0.7×0.7). Preserve lifecycle/geometry preflight, panel motion, bookmarks hover/click, startup/closing and workspace leases; remove/reconcile temporary row backings only when safe. Test white and dark pages, moving bookmarks, hidden bookmarks, no/one/two tab rows, both compact/persistent modes, resize/DPI, no pointer hit region changes. Record mask/height and effective material settings via existing diagnostics only, no content data.
4. DS-M7: sequential consumer migration: top plane → address → Home Search → Hub → Downloads → Library/History → supporting controls. Reuse underlying tokens, avoid double compositing nested controls and avoid changing geometry for styling. Each migration requires source regression, build, CI and actual Zen visual acceptance before legacy owner removal. Preserve no-motion bypass and theme contrast.
